# Ошибки, таймауты и надёжность

Раздел про то, что сеть ненадёжна — и как строить код, который это переживает: ретраи, обработка исключений, offline-first контур.

### Таймауты OkHttp

- Дефолты: `connectTimeout/readTimeout/writeTimeout = 10 с`; `callTimeout` не задан
- Задавайте явно в `OkHttpClient.Builder`; иначе на слабой сети RAN-запрос висит «по умолчанию»
- Ловушка: таймаут ≠ ошибка сервера; `SocketTimeoutException` — кандидат на ретрай

### Что ретраить

- Да: `IOException`, таймаут, HTTP 408/429 (учитывая `Retry-After`), 5xx
- Нет: 400/403/404 — повтор не исправит запрос; 401 — не ретрай, а refresh token
- Экспоненциальный бэкофф: 1с → 2с → 4с + jitter, обязательно лимит попыток

### Исключения и корутины

- Сеть бросает `IOException` (в Retrofit — плюс `HttpException` из `Response.error()`)
- Ловите конкретные типы, **не заглатывайте `CancellationException`** — иначе сломаете отмену корутины
- Оборачивайте вызов в suspend-функцию репозитория: наружу отдаётся `Result`/sealed UiState, а не исключение

### Offline-first намёк

- UI слушает `Flow` из Room; сеть только обновляет базу (`sync()`)
- Схема: «данные сразу из кэша + фоновый refresh» против «спиннер, пока не ответит сервер»
- Периодический sync и повторы — зона `WorkManager`

### Питфоллы и собеседование
- Классика: «что делает ваше приложение без интернета?» — отвечайте через single source of truth в локальной БД
- Проговаривайте состояния: Loading / Content / Error(c Retry)
- Не путайте ретрай и повторную авторизацию — разные флоу с разными триггерами

# Побочные эффекты в Compose

Как выйти из «чистого» мира композиции, не сломав предсказуемость.

### LaunchedEffect и ключи
- `LaunchedEffect(key) { ... }` — запускает корутину в контексте композиции; отменяется при уходе с экрана и при смене ключа.
- Идиома debounce-поиска: `LaunchedEffect(query) { delay(300); search(query) }` — старый запрос отменяется автоматически.
- `LaunchedEffect(Unit)` — эффект «на всё время жизни composable» (одноразовая загрузка, подписка).

### Остальные эффекты
- `SideEffect { ... }` — синхронный код после КАЖДОЙ успешной recomposition (например, синхронизация с аналитикой).
- `DisposableEffect(key)` — для ресурсов с cleanup: `onDispose { ... }` отписывает listener.
- `rememberCoroutineScope()` — корутина, живущая в композиции, для запуска из колбэков (скролл, анимации).

### Питфоллы и собеседование
- Запуск сетевого запроса прямо в теле composable — классическая ошибка: он будет перезапускаться на каждую recomposition.
- `rememberUpdatedState` — если эффект должен видеть свежее значение, но не должен перезапускаться при его смене.
- Собеседование: чем `LaunchedEffect(Unit)` отличается от `DisposableEffect(Unit)` — наличием cleanup-фазы.

# Связи и вложенные объекты

Здесь закрываются вопросы `rmr_*`: `@Embedded`, `@Relation`, связи 1-N и N-M с junction, частичные DTO.

### @Embedded — денормализация
- Вкладывает поля вложенного класса прямо в колонки той же таблицы (`Address` внутри `UserEntity`).
- Конфликт имён решается префиксом: `@Embedded(prefix = "addr_")`.
- Это НЕ связь двух таблиц — данные лежат в одной записи; при чтении Room соберёт объект обратно.

### @Relation — связь при чтении
- Обёртка (`TopicWithQuestions`) поверх entity или POJO; поле с `@Relation(parentColumn, entityColumn, entity = ...)` заполняется Room сам.
- Под капотом — не один JOIN, а два батч-запроса (родители, затем дети) и склейка по ключу в памяти; N+1 не возникает.
- Работает только в результатах `@Query`; внутри `@Entity` не сработает — entity это прямое отображение таблицы.
- 1-N: тип поля `List<ChildEntity>`; N-N — добавляется `associateBy = Junction(CrossRef::class)`.

### Junction для many-to-many
- Промежуточная таблица с двумя внешними ключами и составным `@PrimaryKey`.
- Room сам выполняет запросы по трём таблицам; вручную можно через JOIN, но тогда группировку делаете вы (например, `groupBy` в Kotlin-слое).
- Целостность — через `ForeignKey(onDelete = CASCADE)`.

### Частичные DTO
- `@Relation(projection = ["text"])` — вернуть только нужные колонки ребёнка.
- JOIN + flat POJO — быстрый способ фильтровать/сортировать по ребёнку; группировку делаете сами.
- Ловушка: JOIN дублирует родителя для каждого ребёнка — count-логика и сортировка легко ломаются, если забыть про дубли.

### Питфоллы и собеседование
- Спрашивают: как Room выполняет @Relation (2 запроса, не JOIN), чем @Embedded отличается от @Relation, как сделать many-to-many.
- Смотрите шире: `@DatabaseView`, сырой SQL в POJO, дерево объектов с несколькими @Relation в одной обёртке.
- Ловушка: направление колонок в @Relation — parentColumn на стороне родителя (topic.id), entityColumn — на стороне ребёнка (question.topicId).
- Признак опыта: вы сами ставите вопрос «JOIN или @Relation» и обосновываете выбор (фильтрация по ребёнку → JOIN; реактивный список тем → @Relation).

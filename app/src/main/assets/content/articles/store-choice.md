# Выбор хранилища

Вопросы раздела — про инженерное решение: как по свойствам данных выбрать SharedPreferences/DataStore, Room, файлы или кэш, и как планировать миграции.

### Критерии выбора

- **Форма и объём**: пара скаляров → Preferences DataStore; связанные объекты с запросами → Room; большой блоб «прочитал целиком» → файл в `filesDir`
- **Структура**: нужны связи, фильтры, поиск → SQL (Room); нет структуры → ключ-значение
- **Реактивность**: автообновление UI при изменении данных → `Flow` из Room или DataStore (у SP подписки нет)
- **Доступность**: шаринг с другими приложениями → FileProvider/ContentProvider, общие медиа → MediaStore

### Типовые решения

- Настройки (тема, язык, флаги) → Preferences DataStore
- Предметные данные пользователя (закладки, прогресс, сущности каталога) → Room
- Кэш ответов/превью → `cacheDir` (OkHttp `Cache` для HTTP)
- Экспорт/документы пользователя → `filesDir` + FileProvider или MediaStore

### Миграция

- Room: `Migration(startVersion, endVersion)` + `addMigrations`, схема под git (`exportSchema = true`)
- SP → DataStore: `SharedPreferencesMigration` при создании, перенос при первом чтении
- Ловушка: миграция «на лету» без тестов = потеря данных пользователя в релизе

### Питфоллы и собеседование
- Классика-вопрос: «почему Room, а не JSON в файле?» — атомарность, готовые запросы, Flow, версии схемы
- Не рассказывайте «Room всегда» — для пары настроек это оверкилл, и собеседующий ждёт фразы про DataStore
- Обязательно проговорите offline-first: локальная база = single source of truth, сеть только обновляет

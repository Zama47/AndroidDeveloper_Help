# System Design в Android (System Design 5/5)

Закрывает вопросы sda_001–sda_008: offline-first, sync, push vs pull, клиентский кэш, версионирование API, ловушки мобильного SD.

### Offline-first
- **Room — single source of truth**: UI подписан на Flow из БД; сетевой слой пишет в Room; UI никогда не читает напрямую из сети. Результат: отклик мгновенный, оффлайн работает.
- Мутации — через **outbox**: локальная запись (client_mutation_id, timestamp) → отправка WorkManager-ом с backoff при сети. Идемпотентность сервера = ключ мутации.
- Paging-3: **RemoteMediator** — догрузка страниц в Room по мере скролла, единый источник.

### Синхронизация
- Серверный лог изменений с **монотонным seq/cursor**; клиент тянет `/sync?since=last_seq`, применяет, атомарно сохраняет курсор. Время устройства курсором не является — часы клиента могут расходиться.
- Push (`FCM data`) — сигнал «есть новое», догрузка всё равно через pull/batch — **push не гарантирован** (Doze, OEM-скины, killed-процесс).
- Конфликты: политика заранее (last-writer-wins, монотонный max, сервер побеждает); «кто выигрывает» должно быть ответом, а не догадкой.

### Кэш на клиенте и версионирование API
- Слои: OkHttp HTTP-кэш (ETag/304) + Coil/Glide (media) + Room (domain). Отдача budgeted трафиком и памятью.
- Forward compatibility: клиент **игнорирует неизвестные поля** (kotlinx.serialization `ignoreUnknownKeys`, lenient enums); удалять/менять поля — только через deprecation.
- Версии: URL `/v1/` + окно поддержки; app_version заголовок → фиче-флаги и учёт живых пользователей версии. BFF, если мобильный формат сильно отличается.

### Ловушки мобильного SD-интервью
- Начать с клиентских constraints: качество сети, % офлайна, батарея, устройств.
- Каждое пробуждение радио стоит энергии: батчинг, WorkManager с constraint (NetworkType.UNMETERED), push вместо polling.
- Process death — это не «крash»: состояние сохранять (ViewModel + savedInstanceState), синхронизацию строить в „до-открытия“.
- Android 13+ POST_NOTIFICATIONS, фоновые ограничения, Keystore для секретов — проговорить, когда релевантно.

### Питфоллы и собеседование
- Ошибка кандидата: рисовать только серверную часть. Интервьюер ждёт связку «клиент-сервер»: оффлайн-очередь, sync-курсор, push-фallback.
- Готовый минимальный дизайн-скелет: Room + outbox + WorkManager + `/sync?since` + FCM data-push + индикатор синхронизации в UI.
- Хорошее завершение: «продукт растёт — где будет ломаться» (конфликты мутации, hot Users, лимит нотификаций) — показывает мышление на 2 шага вперёд.

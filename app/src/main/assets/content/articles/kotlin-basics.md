# Синтаксис и null-safety

Эта статья закрывает вопросы ktb_001–ktb_006: val/var, smart cast, safe calls, `?.`, `!!`, элвис, let и companion object.

### Ссылка или значение
- `val` — read-only ссылка: переприсвоить нельзя, но состояние объекта менять можно (`val l = mutableListOf(1)` — add работает)
- `var` — полноценная переменная; в сигнатурах и полях классов предпочитайте val: меньше мутаций — меньше багов
- Ловушка: «val = immutable объект» — это про Java `final`; неизменяемость типу даёт дизайн (data class с val), не модификатор

### Работа с null
- `?.` — safe call: `user?.name` вернёт null без NPE; цепочки `a?.b?.c` прерываются на первом null
- `?:` — элвис: `name ?: "Гость"`, правая часть может быть `throw`/`return` для раннего выхода
- `?.let { }` — блок выполняется только для non-null receiver; `user?.let { println(it.name) }`
- `!!` — снимает проверку на этапе компиляции и рискует `KotlinNullPointerException` в рантайме; в прод-коде вместо него — `checkNotNull()` или явная обработка
- Smart cast: после `if (s != null)` компилятор приводит тип сам; не работает, если нельзя гарантировать неизменность (open var, custom getter) — спасает локальная `val`
- `companion object` — статик-подобный синглтон: члены доступны по имени класса (`User.load()`), без экземпляра; имя объекта по умолчанию — Companion

### Питфоллы и собеседование
- Чаще всего спрашивают разницу `==`/`===`, `!!` vs `?:` и когда smart cast невозможен — готовьте пример с var/open свойством
- Ловушка: безопасная цепочка вида `a?.b?.c?.d` без элвиса «проглатывает» null молча — подумайте, что вернётся и кому это придётся разбирать
- Свежий взгляд: nullability — часть контракта типа; в Java это аннотации-декорации, в Kotlin — компилятор проверяет до запуска

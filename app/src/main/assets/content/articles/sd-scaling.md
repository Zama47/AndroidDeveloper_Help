# Масштабирование (System Design 2/5)

Закрывает вопросы sdsc_001–sdsc_008: vertical vs horizontal, load balancer, stateless, monolith vs microservices.

### Vertical vs horizontal
- **Vertical (scale up)**: мощнее инстанс. Быстро и без рефакторинга, но нелинейная цена, физические пределы, SPOF.
- **Horizontal (scale out)**: N копий за load balancer. Эластично, переживает сбои, но требует stateless и распределённой дисциплины.
- Лайфхак интервью: первый шаг — «профилировать узкое место и масштабироваться вертикально», только потом распределять.

### Load balancer
- Алгоритмы: round-robin, least connections, weighted, **sticky** (cookie/IP-hash) или consistent hashing по user id.
- Sticky нужен, если у инстанса есть локальный кэш/сессия; цена — неравномерная балансировка и потеря кэша при сбое ноды. Замена sticky — внешний кэш (Redis).
- **L4** — по TCP/UDP, дёшево и быстро; **L7** — читает HTTP (path/headers/TLS): роутинг `/api` vs `/static`, canary, TLS-терминация. Практика: L4 на входе, L7 внутри.

### Stateless как принцип
- Состояние внутри процесса мешает масштабу: запись на ноду A, чтение на B. Нужный инвариант: любой инстанс обрабатывает любой запрос.
- Состояние живёт خارج: Redis (сессии, кэш), БД, JWT (пользовательский контекст в токене).
- Отсюда rolling-деплой и autoscaling без остановки.

### Monolith vs microservices
- **Modular monolith** — модули с чёткими границами, один процесс/деплой: старт малого лучший. Распил позже идёт «по швам».
- Микросервисы дают: независимые деплой/масштабирование, стек по задаче. Платят сложностью: сетевые отказы, частичные сбои, eventual consistency, tracing.
- Не «переписывайте всё»: сервисы оправданы, когда источники нагрузки различаются (медиа/поиск/отчёты) — сначала вычленить их.

### Питфоллы и собеседование
- Типовой вопрос: «сервис тормозит — что первое?» Ожидается лестница: профиль → кэш/vertical → LB → БД (реплики → шард).
- Шардирование записей (consistent hashing) в БД — следующий большой шаг; read replicas — более дешёвая мера до него.
- Наблюдаемость — часть дизайна масштабирования: метрики/SLO/алерты, иначе «масштабируете вслепую».
- Ловушка: «микросервисы — как ускорить» — они про организацию команд, не про один тормозящий CPU.

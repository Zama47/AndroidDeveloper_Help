# Очереди и асинхронность (System Design 4/5)

Закрывает вопросы sdq_001–sdq_008: очереди, семантики доставки, idempotency, DLQ, event-driven, порядок в Kafka.

### Зачем очереди
- Развязать продюсера и консьюмера: send и обработка — в разное время; пики сглаживаются, service падения не цепляются.
- Синхронный «email внутри регистрации» — хрупкий долгий запрос. Очередь: event `UserRegistered` → воркер с ретраями.
- Kafka, RabbitMQ, SQS, Pub/Sub; Ключевая разница: Kafka — журнал (replay, порядок по партиции, стриминг), RabbitMQ/SQS — классические очереди (динамика заданий, delays).

### Гарантии доставки
- **At-most-once**: может потерять. **At-least-once**: может задублироваться — стандарт на практике. **Exactly-once**: эффективно = at-least-once + **идемпотентный** консьюмер (dedup-ключ, upsert, `ON CONFLICT`).
- Дубли возникают при потерянных ack/timeout — это норма, не баг. Пишем dedup: таблица обработанных message-id или Redis SETNX.
- Идентичные удары: платежная мутация без idempotency key = двойное списание.

### Отказоустойчивость
- Retry с backoff; неустранимые ошибки → **DLQ (dead letter queue)** после N попыток: не крутить бесконечно и не терять тихо; алерты + runbook + replay после фикса.
- Пойзон-сообщение (битый payload) ломает воркеры по одному — DLQ обязан быть в lẽо по умолчанию.
- Негативный сценарий: консьюмер «падает по краю» — между реальной выработкой и логами — свои transactional outbox, если нужна атомарность записи + публикации.

### Порядок и партиции
- Kafka гарантирует порядок **в рамках партиции**; события с одним ключом (user_id) идут подряд, глобальный порядок не обещан.
- Если бизнесу нужен порядок между ключами — проектируйте это как отдельный шаг, не надейтесь на брокер.
- Событие десериализуется с обновлённым кодом: schema evolution (compatible schema registry), не «пересобрать всё разом».

### Питфоллы и собеседование
- «Kafka гарантирует exactly-once» — неверно для внешних эффектов; сказать это прямо — плюс к пониманию.
- Event-driven уместен, когда результат не нужен немедленно (notification, метрики, fan-out); деньги/авторизация — синхронно.
- Метрики очередей: lag, retries, DLQ-рост; без алертов очередь молча растёт.
- Проговорить backpressure: если продюсер быстрее консумента — lag растёт; лимит/scale/шедулинг продюсера.

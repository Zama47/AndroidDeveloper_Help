# Кэширование и CDN (System Design 3/5)

Закрывает вопросы sdc_001–sdc_008: слои кэша, invalidation, TTL, stampede, CDN, клиентский кэш.

### Паттерны
- **Cache-aside**: сервис сам смотрит в Redis → промах → БД → кладёт в кэш; при записи — инвалидирует ключ. Самый частый паттерн, и при нём чаще всего ошибаются в инвалидации.
- **Write-through**: запись идёт в кэш и БД синхронно (консистентно, дорого). **Write-behind**: в кэш сразу, в БД асинхронно (быстро, риск потери хвоста).
- **Read-through**: сам кэш подгружает из БД (библиотечный контракт, less гибкий).

### Invalidation и TTL
- «Только две сложные вещи в CS: invalidation и naming». Стратегии: TTL-only, event-based (инвалидация по записи), version-based (теги/префиксы версий).
- TTL по цене ошибки: лента — минута-час, настройки — секунды, immutable-файлы — годы + `Cache-Control: immutable`.
- **Инвалидация при записи**: обновлять кэш/пургу CDN; после сбоя кэша — warm-up (prewarming).

### Stampede и hot key
- **Cache stampede** / thundering herd: горячий ключ протух → тысячи одновременных промахов бьют в БД.
- Лечение: single-flight (лок по ключу, остальные ждут), TTL + jitter, soft-обновление до истечения, локальная LRU-прослойка (L1) перед Redis (L2).
- Наблюдаемость: hit ratio, evictions, latency origin vs cache, алерты на drop hit.

### CDN и клиентский кэш
- CDN: статические, медиа, immutable-файлы с hash в URL (перезаливка = новый URL). Динамический API — только с осторожностью и по заголовкам.
- Клиентский HTTP-кэш: **ETag / If-None-Match → 304 Not Modified** — переиспользование тела без перекачки; OkHttp-кэш, Coil/Glide для изображений в памяти и на диске.
- Полное кэширование мобильного приложения = Room (доменные данные) + HTTP-кэш (API) + media-cache (Coil) + CDN (edge).

### Питфоллы и собеседование
- Ловушка: «добавим кэш везде» — кэш добавляет invalidation ошибки, устаревание и новые компоненты отказов; кэшировать измеренные горячие места.
- Спрашивают: «чем Redis от Memcached/локального HashMap» — структуры, TTL per key, атомарные операции, persistence, pub/sub; HashMap элементарно небезопасен между инстансами.
- В мобильном контексте важно показать два слоя: серверный (Redis/CDN) и клиентский (Room + HTTP-кэш), и что write path у обоих ведёт к инвалидации.
